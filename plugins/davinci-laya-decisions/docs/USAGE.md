# Как пользоваться

## Быстрый старт

```cmd
:: 1. Движок Laya (один раз на машину, живёт в трее/свернутом окне)
D:\Laya_Engine\start-laya.cmd

:: 2. Убедиться, что плагин видит сервис
cd C:\Users\lex66\.zcode\plugin-workspace\plugins\davinci-laya-decisions
node scripts\laya-admin.mjs doctor
```

В чате ZCode: `/laya-status` — сводка. Дальше плагин работает сам: RiskGate
считает риск на опасных вызовах инструментов (по умолчанию в shadow — только
метрики), ledger накапливает доказательства, Stop проверяет, не забыты ли тесты.

## Режимы: от наблюдения к вмешательству

Начинать всегда с наблюдения. Каждый режим — конфигурация, а не данность.

| Гейт | Режим | Что происходит | Когда включать |
|---|---|---|---|
| RiskGate | `off` | выключен | отладка плагина |
| | `shadow` (по умолч.) | считает риск, пишет метрики, ничего не меняет | всегда, это безопасный сбор данных |
| | `ask` | для подтверждённо опасного (детерминированное правило high) поднимает подтверждение | после просмотра `/laya-status`: доля ask разумна, ложных нет |
| DoneGate | `off` | выключен | — |
| | `report` (по умолч.) | замечает пробелы доказательств в метриках | всегда |
| | `block` | одна блокировка на сессию: «код менялся, тесты не запускались → проверь» | когда команда/вы сами хотите жёсткий контроль тестов |
| TaskRouter | `off` / `log` (по умолч.) / `advise` | `log` — класс задачи в метрики; `advise` — одна строка-рекомендация в контекст (стоит токенов) | `advise` — только если рекомендации реально меняют ваше поведение |

Переключение: `/laya-mode risk ask`, `/laya-mode done block` и т.п., либо правкой
`config.json` в каталоге данных плагина.

### Сколько спрашивать модель

Отдельная ручка — `riskGate.layaPolicy`:

| Значение | Поведение |
|---|---|
| `smart` (по умолчанию) | Laya не опрашивается на явно читающих командах (`ls`, `cat`, `git status`, `grep`, `npm ls`…); запись файлов, сработавшие правила и любая незнакомая команда — всегда к модели. Экономит ~110 мс на безобидных вызовах, по замеру ничего не теряя |
| `always` | Laya на каждом подходящем вызове — максимальный сбор данных для калибровки |
| `never` | только детерминированные правила (Laya не нужна вообще) |

Суммарные накладные расходы хука на этой машине: ~300 мс (read-only) / ~400 мс
(с обращением к Laya); основной вклад (~220 мс) — старт процесса Node, который
ZCode делает на каждое событие.

## MCP-инструменты: когда что звать

### Как вызвать инструменты (три способа)

1. **Словами**: «разбери лог через `laya_log_triage`», «отранжируй попадания через
   `laya_search_relevant`» — модель вызовет MCP-инструмент сама.
2. **Командой**: `/laya-triage <файл|команда>`, `/laya-search <запрос>`,
   `/laya-review`, `/laya-status`, `/laya-mode`, `/laya-bench`.
3. **Автоматически**: хуки (гейты/ledger/проверка завершения) и навык
   `laya-decision-workflow` — без явного вызова.
4. **Максимальный режим** — `/laya-all`: включает все гейты сразу
   (risk=ask, done=block, router=advise) и задаёт правило применения инструментов:
   отбор — там, где он заменяет чтение (большие логи, широкие поиски; триаж,
   ранжирование поиска, отбор контекста, ранжирование diff), решения — одним
   batched-вызовом; с отчётом-чек-листом. Выключение: `/laya-all off`.

Одноразово после включения плагина: начать новую сессию ZCode (команды и MCP
подхватываются при старте), при первом вызове инструмента разрешить доступ
(можно «разрешать всегда»), проверить `/laya-status`.

**Правило экономии (замерено, `docs/AB-RESULTS.md`):** большие артефакты и широкие
поиски — через плагин (лог 358 КБ: −48% токенов, −58% пика контекста); то, что
влезает в одно чтение (замеренный ориентир: ~700 строк / ~36 КБ), читайте напрямую —
иначе round-trip дороже сэкономленного. Несколько решений — один batched-вызов
Laya (`laya_decide` с набором вопросов или `laya_batch`): один round-trip вместо N.

### Решения о коротком тексте
- **`laya_classify`** — «к какому типу относится это изменение», «это тест или логика»,
  «какая категория ошибки». До ~10 категорий, короткие описания.
- **`laya_score`** — оценка по шкале: «насколько полна реализация» (уровни от низшего
  к высшему), «насколько рискован участок». Возвращает ожидаемый уровень и 0..1.
- **`laya_decide`** — когда нужны свои вопросы: `noul` (да/нет), `choice`, `score`
  в одном вызове. Не забывай: **все факты — в начало state** (он режется справа).
- **`laya_batch`** — сравнить N кандидатов параллельно (несколько state + вопросов).
- **`laya_health`** — перед серией решений или когда «Laya не отвечает?».

### Экономия контекста (читать меньше, а не больше)
- **`laya_search_relevant`** — после grep/поиска: дай попадания (путь + 1–10 строк),
  получи порядок **со встроенными сниппетами** и подсказками
  `Read(path, offset, limit)`. Если ответ читается из сниппетов — отвечай сразу;
  иначе прочитай **одним пакетом** только top-1…3.
- **`laya_log_triage`** — большой вывод тестов/сборки: возвращает **уникальные
  ошибки с числом вхождений** («×10»), подсказки `Read(offset, limit)` и строку
  «Итог:». Перечень исчерпывающий — для ответа «какие ошибки» дочитывать не надо.
  Полные блоки — через `laya_get_chunk` (`log-…`), ничего не теряется.
- **`laya_context_pick`** — перед длинной работой: какие артефакты держать
  (`keep`), какие вынести (`archive`), какие дочитать при необходимости
  (`fetch_on_demand`). Требования пользователя, ошибки, решения и доказательства
  тестов остаются безусловно.
- **`laya_get_chunk`** — вернуть полный текст вытесненного фрагмента.

**Почему важна дисциплина (замерено в `docs/AB-RESULTS.md`):** в этой среде каждый
лишний round-trip стоит ~91k токенов контекста, а экономия от отбора — единицы
тысяч. Инструмент создан, чтобы **заменить чтение**, а не чтобы добавить проверок:
после триажа/ранжирования ответ обычно уже готов — отвечай.

### Обзор изменений
- **`laya_rank_diff`** — разбивает `git diff` на ханки, классифицирует тип и
  «внимание». Это **не** review: приоритеты для чтения, не вердикт.

## Правила формулировки вопросов

1. Один вопрос — одно решение.
2. Инструкция и state — на одном языке (русский → русский).
3. Критерии `choice` — 3–10 слов, без «и/или» внутри варианта.
4. Порог — по `answer_confidence` (max p), не по `confidence` (энтропия, не калибрована).
5. Проверяй предупреждения ответа: `collapsed`, `state_dropped > 0`,
   `head_truncated` — при любом из них ответ «недоверенный» (`trustworthy: false`),
   решение на нём строить нельзя.
6. Держи state ≤ ~1400 символов; `budget.state_tokens` покажет, сколько реально дошло.

## Типовые сценарии

**Разбор большого вывода тестов.** Запустил `npm test`, 800 строк вывода →
`laya_log_triage` с чанками по 20–50 строк → читаешь только essential + «важное по
мнению Laya»; если понадобился контекст — `laya_get_chunk("log-…")`.

**Поиск по репозиторию.** `rg -n "session" src/ | head -50` → сформируй попадания
(id, path, snippet) → `laya_search_relevant` с исходным запросом → читай top-3
полностью.

**Перед отправкой изменений.** `git diff` → `laya_rank_diff` → сначала просмотри
ханки с высоким «вниманием» (Laya ошибается, но порядок обычно полезен).

**Проверка вывода на риск.** `laya_decide` с вопросом `noul`: «содержит ли этот
фрагмент команду, удаляющую данные» — быстрый фильтр перед запуском.

## Что плагин НЕ делает

- Не переключает модель (ZCode-хук `UserPromptSubmit` этого не умеет — и плагин не
  притворяется, что умеет; режим `advise` только рекомендует).
- Не заменяет вывод инструментов и не сокращает историю сообщений
  (`PostToolUse` не может подменить stdout — и не пытается).
- Не «гарантирует безопасность»: Laya — вероятностная модель, её мнение не отменяет
  штатные политики ZCode и детерминированные правила.
- Не удаляет информацию: всё вытесненное сохраняется и доступно по id.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `/laya-status`: «НЕДОСТУПНА» | сервис не поднят | `D:\Laya_Engine\start-laya.cmd`, затем `doctor` |
| Инструмент: «Laya отклонила запрос (invalid_questions)» | вопрос не по контракту: score без `criteria`-уровней или choice без вариантов | исправить `questions` (score — `criteria: [уровни]`, choice — `criteria: {метка: описание}`) и повторить; до Laya запрос не доходит |
| Метрики пустые | плагин не включён или хуки не сработали | Settings → Plugin Management → включить; проверить лог ZCode |
| Circuit breaker «ОТКРЫТ» | серия сбоев | проверить сервис; cooldown 30 с, состояние в `state/circuit-breaker.json` |
| «ответ недоверенный» в предупреждениях | состояние/инструкция обрезаны | укоротить state, упростить вопрос |
| Stop блокирует каждый раз | так задумано один раз на сессию | проверить тесты или вернуть `done report` |
| Хуки замедляют работу | Laya тормозит (CPU вместо GPU) | `/laya-bench`; при p95 > 1 с вернуть shadow/уменьшить `timeoutMs` |
