# A/B-эксперименты: плагин против отсутствия плагина

Здесь лежат воспроизводимые замеры ценности плагина `davinci-laya-decisions`.
Цель — заменить «должно быть быстрее» на числа и показать, где выгода есть,
а где её нет.

## Метод

Один агент-субагент (`general-purpose`, полный набор инструментов) выполняет одну
и ту же задачу в одном из двух режимов. Отличается только способ обработки
информации:

| Режим | Как работает |
|---|---|
| **A — без плагина** | читает артефакт целиком (как агент без инструментов плагина) |
| **C — с плагином** | сначала детерминированный триаж/ранжирование (`laya-cli log-triage` / `search-relevant`), затем читает только нужное |

Оба режима получают одинаковый базовый контекст (один и тот же тип агента,
одинаковая по формулировке задача), поэтому разница в замерах объясняется именно
способом обработки. Измеряется журнал ZCode `~/.zcode/cli/rollout/model-io-sess_subagent_*.jsonl`
(скрипт `analyze-io.mjs`):

- **пик контекста** (`inputTokens` максимум) — сколько токенов осело в контексте
  навсегда и будет оплачиваться в каждом последующем вызове;
- **новые токены промпта** (`inputTokens − cacheReadTokens`) — то, что реально
  «добавлено» за эпизод;
- **сумма inputTokens** и число вызовов — общая стоимость эпизода (каждый вызов
  пересылает контекст; кэш дешевле, но не бесплатен);
- **время** (`durationMs`) и **правильность ответа** (recall/точность по фактам).

Артефакты детерминированы (`make-artifacts.mjs`), поэтому повторные прогоны
сравнимы. Каждый режим прогоняется несколько раз — разброс между прогонами
существенный (агент сам выбирает, сколько читать), поэтому сравнение по медиане.

## Задачи

1. **Разбор лога** — `log-700.txt` (700 строк, 35.7 КБ, три зарытые ошибки среди
   шума прогресса/предупреждений). Ответ: тип, файл, строка каждой ошибки.
2. **Поиск по репозиторию** — где в `D:\Laya_Engine` режется состояние по бюджету,
   какие поля телеметрии есть, где формируется `budget` в HTTP-ответе.
