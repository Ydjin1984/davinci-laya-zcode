# Laya: рабочий процесс типизированных решений

Laya — локальный decision-engine (`127.0.0.1:8095`, модель ~322M). Она не генерирует текст и не пишет код: она отвечает на **типизированные вопросы** о коротком тексте (`choice`, `score`, `noul`) за один forward pass (~50–80 мс). Используй её там, где решение нужно быстро и дешево, а не там, где нужны рассуждения.

Инференс локальный и бесплатный, но **каждый вызов инструмента — это round-trip главной (платной) модели**. Он оправдан, только если заменяет чтение, которое иначе осело бы в контексте целиком; числа и метод — `docs/AB-RESULTS.md`.

## Когда вызывать

**Вызывай:**
- Нужно выбрать одну из 2–10 категорий для короткого фрагмента (тип изменения, класс задачи, категория ошибки).
- Нужна бинарная проверка («содержит ли блок ошибку», «изменит ли команда состояние»).
- Нужна грубая оценка по шкале (сложность, риск, уверенность).
- Нужно отранжировать найденные попадания/логи, чтобы читать только важное (`laya_search_relevant`, `laya_log_triage`).
- Нужно решить, что оставить в контексте (`laya_context_pick`).

**Не вызывай:**
- Для генерации/написания кода — Laya этого не умеет.
- Для «полного security review» или «аудита» — это ансамбль фактов, а не классификатор.
- Для каждого файла подряд: сначала бесплатный отбор (grep/rg/поиск), затем Laya на коротком списке.
- Там, где артефакт влезает в одно чтение или попаданий десятки, — в обычном режиме читай напрямую: отбор не окупится. В Laya-first пороги ниже (см. ниже).

## Laya-first (активный /laya-all)

Если в конфигурации `layaAll=true` (это ставит `/laya-all`), Laya — режим по умолчанию для отбора, поиска, фильтрации и решений, а не опциональный кросс-чек. Пороги ниже стандартных:

| Ситуация | Действие |
|---|---|
| Вывод команды/инструмента >100 строк или >8 КБ | `laya_log_triage` первым шагом |
| Поиск >30 попаданий | `laya_search_relevant` |
| Выбор/фильтрация/ранжирование >5 элементов | `laya_batch` (все вопросы одним вызовом) |
| Diff >3 ханков | `laya_rank_diff` |
| >5 артефактов в контексте | `laya_context_pick` |

Для меньших объёмов читай напрямую, но checkpoint обязателен: один `laya_classify` текущего действия (правка/анализ/поиск/решение/тривиально). Это не «вызывать всё подряд», а «по умолчанию использовать Laya там, где есть отбор или решение»; один вызов на ход — цена режима «always».

**Обязательный checkpoint:** каждый пользовательский ход — минимум один явный `laya_*` вызов. Если пороги не сработали, вызови `laya_classify` действия; без него Laya-first не считается выполненным.

В финале обязателен отчёт об использовании: какие инструменты вызваны, что они заменили, сколько токенов не попало в контекст; если категория не использована — укажи фактический размер и причину. Laya — вероятность, не доказательство: доменные факты проверяй по бинарнику/коду/тестам; при расхождении верь детерминированным данным.

Если пользователь написал `/laya-all` текстом, а не вызвал slash-команду, прочитай `commands/laya-all.md` и выполни её шаги. Одной загрузки скилла недостаточно.

## Как формулировать вопросы

1. **Один вопрос — одно решение.** Не объединяй «ошибка ли это и насколько опасно» в один вопрос.
2. **Один вызов — все вопросы.** Независимые вопросы складывай в один вызов `laya_decide` (набор `questions`) или `laya_batch` (N состояний): один round-trip вместо N, точность та же.
3. **Критерии — короткие описания**, по 3–10 слов, без «и/или» внутри одного варианта.
4. **Формулировка инструкции — на языке текста.** Русский state → русская инструкция (модель мультиязычная, но смешение языков в одном запросе ухудшает ответ).
5. **Все факты — в начало state.** Состояние режется справа: операция, цель, признаки идут первыми, длинные подробности — последними.
6. **Порог ставь по `answer_confidence`** (max p), не по `confidence` (энтропия, не калибрована).
7. **Проверяй предупреждения**: `collapsed` (варианты неразличимы), `state_dropped > 0` (текст обрезан), `head_truncated` (инструкция обрезана). Если есть предупреждение — ответу не доверяй, укороти вход или упрости вопрос.

## Границы доверия

- Laya даёт **вероятность**, а не доказательство. `data_loss = 0.72` — это не факт, а оценка.
- **Детерминированные факты важнее Laya**: если `git status` говорит, что есть незакоммиченные изменения, а Laya говорит «риска нет» — верь git.
- **Низкий риск от Laya никогда не расширяет разрешения.** Только повышает внимание (ask), никогда не разрешает и не отменяет запреты.
- При недоступности Laya — продолжай работу штатно, отметь неопределённость, не выдумывай вердикт.

## Лимиты движка (по официальной документации Laya)

- Наш чекпоинт — multilingual (mmBERT-base, 322M): читает **до 8192 токенов**
  (`max_len=8192` на запрос), но сервис по умолчанию работает с бюджетом **1024**
  (шипнутый дефолт чекпоинта). Всё, что не поместилось, режется справа — потеря
  видна в `state_dropped`/`state_truncated`; не игнорируй эти предупреждения.
- Точность: уверенно примерно **до ~4000 токенов** текста перед вопросом; дальше
  документация требует мерить на своих данных.
- `head_max_len=256` — бюджет вариантов: в один `choice` держи **до ~20 вариантов**,
  иначе варианты становятся неразличимыми.
- Инструменты и гейты плагина сами держат состояния короткими (гейт ≤1400 символов,
  фрагменты инструментов ≤~1300 символов) — это осознанный бюджет, а не усечение.
- **Осторожно с длинными запросами**: после одного forward-pass на ~8 тыс. токенов
  инстанс переходит в медленный режим (~2,5 с на любой вызов вместо десятков мс)
  до перезапуска (`D:\Laya_Engine\stop-laya.cmd`, затем `start-laya.cmd`).
  Отправляй длинный документ, только если он реально нужен, и будь готов
  перезапустить сервис.

## Контекстные инструменты (экономия без потерь)

Порядок работы с большим выводом:

1. Сначала обычный поиск (grep/rg/glob) — он дешёвый и точный.
2. Затем `laya_search_relevant` (попадания → путь + snippet) — Laya упорядочивает.
3. Для логов: `laya_log_triage` — возвращает **уникальные ошибки с количеством вхождений** («×10»), готовые подсказки `Read(offset, limit)` и отдельную строку «Итог:». Перечень исчерпывающий: для ответа на «какие ошибки» повторные чтения **не нужны**.
4. Читай файл только если нужен контекст вокруг конкретного места — и **одним пакетом** (несколько Read в одном сообщении), только top-1…3.
5. Полные блоки всегда доступны через `laya_get_chunk(id)`.

**Экономический контракт (измерен, `docs/AB-RESULTS.md`):** артефакт, осевший в контексте, оплачивается в каждом следующем вызове сессии. Отсюда — правило выбора:

| Артефакт / задача | Правило |
|---|---|
| Влезает в одно чтение (замер: лог 700 строк / 36 КБ) | читать напрямую: отбор добавляет round-trip, который нечем оплатить |
| Не влезает (лог 7000 строк / 358 КБ) | отбор первым шагом: пик контекста −58%, сумма токенов −48% против чтения целиком |
| Поиск: десятки попаданий | rg + прямое чтение |
| Поиск: сотни попаданий | `laya_search_relevant` — окупается здесь, а не на 20 |
| N решений | один batched-вызов: каждый вызов — отдельный round-trip |

Недисциплинированное применение («все инструменты сразу», дочитывание блоков после триажа) в замере дало +177% токенов. **Инструмент отдаёт готовый ответ — отвечай**; проверочные чтения после триажа — главный способ потерять больше, чем сэкономил. Гейты в shadow/report/log добавляют 0 токенов контекста; платные текстовые строки — только `router=advise` (на каждый промпт) и `sessionContext=on`.

**Никогда не удаляй** требование пользователя, ошибку, принятое решение или путь: если инструмент отправил их в archive, они доступны через `laya_get_chunk`, но убедись, что контекст не потерял смысл.

## Сводка экономии (финал любой работы с Laya)

После задачи, где применялись инструменты Laya, закрой ответ короткой сводкой
(3–6 строк + таблица): что обработано отбором, сколько токенов не попало в
контекст и сколько это в долларах. Числа — из размеров артефактов и выводов
инструментов, а не «на глаз»:

1. **Балласт артефакта** (токены, не осевшие в контексте): `байты / 2.8` или
   `строк × 18` — коэффициенты замерены на логах (`docs/AB-RESULTS.md`:
   35,7 КБ → 12,8 тыс. ток., 358 КБ → 132,9 тыс. ток.).
2. **Что всё же вошло в контекст**: `строк вывода инструмента × 18` (оценка).
3. **Чистая экономия токенов** = п.1 − п.2. Отдельной строкой — стоимость отбора:
   каждый вызов Laya это +1 round-trip (пересылка текущего контекста; в замере
   база ~91 тыс. ток., в основном по цене кэша — в деньгах это копейки).
4. **Деньги** — по ценам DeepSeek (страница Pricing, снято 2026-10-15; перед
   использованием сверь актуальность). Пик: 01:00–04:00 и 06:00–10:00 UTC,
   пн–пт; всё остальное — непик, цена вдвое ниже. Считай по строке модели
   текущей сессии:

| Модель, $/1M токенов | Вход: кэш-промах | Вход: кэш-попадание | Выход |
|---|---|---|---|
| deepseek-flash | 0.3 / 0.15 | 0.006 / 0.003 | 1.2 / 0.6 |
| deepseek-v4-pro | 1.32 / 0.66 | 0.044 / 0.022 | 3.96 / 1.98 |

   Формат «пик / непик».
5. **Экономия, $** ≈ `балласт × (цена_входа + (T−1) × цена_кэша)`, где T — число
   вызовов модели после отбора; если T неизвестно — так и скажи и дай «разово»
   (`× цена_входа`) с пометкой допущения. Выход не меняется — его не считаем.

Пример сводки:

| Показатель | Значение |
|---|---|
| Обработано отбором | лог 7 000 строк / 358 КБ → уникальные ошибки (с «×повторами») |
| Не попало в контекст | ≈ 128 тыс. токенов |
| Вошло в контекст | ≈ 1 тыс. токенов → чистая экономия ≈ 127 тыс. токенов |
| Стоимость отбора | 1 вызов Laya (round-trip, в основном кэш) |
| Экономия, $ (непик / пик) | ≈ **$0.03 / $0.06** за 30 вызовов после отбора (разово: $0.02 / $0.04) |

Если данных для оценки нет (например, неизвестен размер артефакта) — не выдумывай
числа: скажи, каких данных не хватает. Сводка сама стоит токенов — не растекайся.

## Диагностика

- `/laya-status` — доступность, чекпоинт, режимы, метрики.
- `/laya-bench` — замер латентности перед включением активных режимов.
- `/laya-mode` — переключение режимов гейтов.
- `/laya-review` — ранжирование текущего diff (не review!).
- `node scripts/laya-admin.mjs doctor` — самодиагностика интеграции.
