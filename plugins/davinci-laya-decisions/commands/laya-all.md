# Полный режим Laya

Включи максимальный режим использования Laya и работай в нём до конца задачи.
Аргумент команды: $ARGUMENTS. Если аргумент не указан — используй `on`; `off` возвращает наблюдение.
Если пользователь написал `/laya-all` в сообщении, а не вызвал команду, прочитай этот файл и выполни шаги: одной загрузки скилла недостаточно.

**Шаг 1 — проверить аргумент и переключить режимы.** Сначала определи режим сам:
пустой аргумент → `on`, ровно `on` или `off` → как указано, любое иное значение
(включая фразу) → откажись, назови допустимые значения и **не вызывай `all`**.
Неизвестное значение раньше включало режим, поэтому проверка обязательна.

Подставь вычисленный `on` или `off` вместо `<on|off>` и выполни:

```bash
# ZCODE_PLUGIN_ROOT в Bash может быть не задан: берём installPath из реестра
# установленных плагинов. Это переживает обновление версии плагина.
PLUGIN_ROOT="${ZCODE_PLUGIN_ROOT:-$(node -e 'try{const fs=require("fs"),path=require("path"),os=require("os");const f=path.join(os.homedir(),".zcode","cli","plugins","installed_plugins.json");const j=JSON.parse(fs.readFileSync(f,"utf8"));const p=(j.plugins||[]).find(x=>x.name==="davinci-laya-decisions");if(!p)process.exit(2);process.stdout.write(p.installPath)}catch(e){process.exit(2)}')}"
test -f "$PLUGIN_ROOT/scripts/laya-admin.mjs" || { printf 'Не найден laya-admin.mjs: %s\n' "$PLUGIN_ROOT" >&2; exit 2; }
node "$PLUGIN_ROOT/scripts/laya-admin.mjs" status
node "$PLUGIN_ROOT/scripts/laya-admin.mjs" all "<on|off>"
node "$PLUGIN_ROOT/scripts/laya-admin.mjs" status
```

Скрипт отвергает любое значение, кроме `on`/`off` (пусто = `on`), при ошибке
выходит с ненулевым кодом и ничего не записывает; после записи он проверяет
фактическое содержимое конфигурации. Это ставит `risk=ask` (опасные вызовы
спрашивают подтверждение), `done=block` (одна возвратная проверка, если код
менялся без тестов), `router=advise` (класс задачи строкой в контекст),
`sessionContext=on`; `off` возвращает shadow/report/log/off. `all on` также ставит
`layaAll=true` (Laya-first), `off` — `false`; статус показывает Laya-first.

Стоимость режимов (замерено): гейты в shadow/report/log добавляют **0 токенов**
контекста; платят только текстовые режимы — `router=advise` приходит строкой на
**каждый** промпт (точность совета ≈58%), `sessionContext` — одна строка на сессию.
Если приоритет — экономия платных токенов, после переключения выполни
`node "$PLUGIN_ROOT/scripts/laya-admin.mjs" mode router log` (в том же shell, где
определён `PLUGIN_ROOT`; иначе повтори его определение из шага 1): гейты останутся
активными.

**Шаг 2 — Laya-first: применять инструменты по умолчанию.** Laya локальна и бесплатна,
но каждый её вызов — это round-trip главной (платной) модели. В этом режиме пороги
ниже стандартных: Laya используется везде, где есть отбор, поиск, фильтрация или
неоднозначное решение, а не только на очень больших артефактах. Для мелких фрагментов
чтение всё ещё дешевле; пропуск категории допустим только с фактическим размером и
причиной в финальном отчёте.

**Обязательный checkpoint.** Каждый пользовательский ход в Laya-first должен содержать
минимум один явный `laya_*` вызов. Если ни один порог не сработал (мелкая правка,
короткий вывод, одно решение), вызови `laya_classify` на текущем действии с категориями
`правка / анализ / поиск / решение / тривиально` — один короткий вызов. Ход без
Laya-вызова — нарушение режима; в финале объясни, почему checkpoint не сработал.

| Точка работы | Инструмент | Правило Laya-first |
|---|---|---|
| Вывод команды/инструмента >100 строк или >8 КБ | `laya_log_triage` | отбор первым шагом; ответ — из вывода (уникальные ошибки с `file:line`, «×N», «Итог:»), повторные чтения не нужны |
| Вывод меньше порога | `laya_classify` (checkpoint) | читать напрямую; checkpoint — один короткий вызов на действие |
| Поиск: >30 попаданий | `laya_search_relevant` | ранжирование и сниппеты одним вызовом; читать top-1…3 одним пакетом |
| Поиск: ≤30 точных попаданий | rg/grep | прямое чтение дешевле ранжирования |
| Выбор/фильтрация/ранжирование >5 элементов | `laya_batch` | все вопросы — одним вызовом; один round-trip вместо N; порог по `answer_confidence` |
| Diff >3 ханков | `laya_rank_diff` | порядок внимания по ханкам, потом читать верхние |
| >5 артефактов в контексте | `laya_context_pick` | keep / archive / fetch_on_demand; pinned не трогать |
| Любое неоднозначное решение | `laya_classify` / `laya_score` / `laya_decide` | один вызов на все вопросы; Laya — вероятность, факты проверяй |
| Проверка сервиса | `laya_health` | при сомнениях в доступности |

Пороги — значения по умолчанию для активного `/laya-all`, а не рекомендация. Laya не
источник истины: доменные факты проверяй по коду/бинарнику/тестам; при расхождении верь
детерминированным данным.

**Шаг 3 — отчитайся чек-листом** (2–5 строк): какие инструменты применил, что дали
(какие ошибки нашлись, какие решения приняты). Для каждого пункта таблицы — «применён»
или «не применим: фактический размер и причина». Вызов ради галочки не создавай, но и не
пропускай категорию без измерения. **Отчёт об использовании Laya обязателен** даже если
ни один инструмент не вызван.
**Сводка экономии** — если инструменты реально применялись: таблица
(обработано / сэкономленные токены / $) по форме из навыка `laya-decision-workflow`,
раздел «Сводка экономии»; числа по замерам. Если не применялись — одной строкой
«Laya-инструменты не применялись: отбирать было нечего, экономия не измерялась»
вместо таблицы с нулями. Не выдавай нули за результат.

Правила, чтобы режим приносил пользу, а не расход:
- инструмент отдал готовый ответ — отвечай по нему; максимум одно пакетное чтение top-1…3, если нужен контекст вокруг места;
- мелкие файлы и точные выборки (≤30 попаданий) — читать напрямую, но checkpoint `laya_classify` всё равно сделать;
- в Laya-first пороги из таблицы — значения по умолчанию; пропуск только с фактическим размером и причиной;
- state для Laya — короткий, факты в начале; несколько вопросов — один вызов;
- не дочитывать то, что уже есть в выводе инструмента (это прямая экономия токенов).

Отключение в любой момент: `/laya-all off`.

## Адресное применение и проверка режима

Допускай только on/off, без аргумента on. Неизвестное значение отклоняй до CLI: оно может включить режим. Прочитай status до и после переключения. Проверь фактические risk/done/router/sessionContext/layaAll и путь конфигурации. Ошибку health отличай от ошибки записи.

| Условие | Действие |
|---|---|
| Инструмент помогает текущей задаче | Применить его с проверкой результата |
| Малый достаточный фрагмент | Читать напрямую |
| Усечение или низкая уверенность | Расширить данные и проверить исходник |
| Противоречие или сбой Laya | Продолжить обычными инструментами |
| Решение о безопасности или завершении | Требовать факты и подходящие проверки, а не confidence |

Не вызывай все инструменты ради чек-листа. Повторяй запрос только при новых данных. Pinned-контекст сохраняй; архив должен допускать восстановление. Ранжирование не отменяет проверку критичного кода. Laya не отменяет штатные разрешения.

Режим записывается в конфигурацию и не отключается сам по окончании задачи. Off задаёт shadow/report/log/sessionContext=off, а не восстанавливает прежние индивидуальные значения. В отчёте — фактический режим, полезные результаты и ограничения; экономия только по измерению.
