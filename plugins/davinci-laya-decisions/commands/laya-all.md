# Полный режим Laya

Включи максимальный режим использования Laya и работай в нём до конца задачи.
Аргумент команды: $ARGUMENTS. Если аргумент не указан — используй `on`; `off` возвращает наблюдение.

**Шаг 1 — переключить режимы:**
```bash
cd "${ZCODE_PLUGIN_ROOT}" && node scripts/laya-admin.mjs all ${ARGUMENTS:-on}
```
Это ставит `risk=ask` (опасные вызовы спрашивают подтверждение), `done=block` (одна
возвратная проверка, если код менялся без тестов), `router=advise` (класс задачи
строкой в контекст), `sessionContext=on`.

Стоимость режимов (замерено): гейты в shadow/report/log добавляют **0 токенов**
контекста; платят только текстовые режимы — `router=advise` приходит строкой на
**каждый** промпт (точность совета ≈58%), `sessionContext` — одна строка на сессию.
Если приоритет — экономия платных токенов, после переключения выполни
`node scripts/laya-admin.mjs mode router log`: гейты останутся активными.

**Шаг 2 — применять инструменты по правилу окупаемости.** Laya локальна и бесплатна,
но каждый её вызов — это round-trip главной (платной) модели. Инструмент оправдан,
только если он **заменяет чтение**, а не добавляет проверок: на замерах
недисциплинированное применение дало +177% токенов, применение по правилу — −48%
(числа и метод — `docs/AB-RESULTS.md`).

| Точка работы | Инструмент | Правило |
|---|---|---|
| Вывод больше одного чтения (лог, тесты, сборка, дамп) | `laya_log_triage` | отбор первым шагом; ответ — из вывода (уникальные ошибки с `file:line`, «×N», «Итог:»), повторные чтения не нужны |
| Вывод влезает в одно чтение (замер: лог 700 строк / ~36 КБ) | — | читать напрямую; отбор добавит round-trip, который нечем оплатить |
| Поиск: сотни попаданий | `laya_search_relevant` | ранжирование и сниппеты одним вызовом; читать top-1…3 одним пакетом |
| Поиск: десятки точных попаданий | rg/grep | прямое чтение дешевле ранжирования (в замере окупается на сотнях) |
| Много артефактов в длинной задаче | `laya_context_pick` | keep / archive / fetch_on_demand; pinned не трогать |
| Перед просмотром изменений | `laya_rank_diff` | порядок внимания по ханкам, потом читать верхние |
| Любое решение: выбор / оценка / да-нет | `laya_classify` / `laya_score` / `laya_decide` | все вопросы — **одним** вызовом (`laya_batch` для N состояний): один round-trip вместо N; порог по `answer_confidence` |
| Проверка сервиса | `laya_health` | при сомнениях в доступности |

**Шаг 3 — отчитайся чек-листом** (2–5 строк): какие инструменты применил, что дали
(какие ошибки нашлись, какие решения приняты). Для каждого применимого пункта таблицы —
«применён» или «не применим: причина». Вызов ради пункта чек-листа не создавай.
**Сводка экономии** (обработано / сэкономленные токены / $) — обязательной таблицей
по форме из навыка `laya-decision-workflow`, раздел «Сводка экономии»: числа по
замерам, не выдуманные.

Правила, чтобы режим приносил пользу, а не расход:
- инструмент отдал готовый ответ — отвечай по нему; максимум одно пакетное чтение top-1…3, если нужен контекст вокруг места;
- мелкие файлы и точные выборки (десятки попаданий) — читать напрямую, без отбора;
- state для Laya — короткий, факты в начале; несколько вопросов — один вызов;
- не дочитывать то, что уже есть в выводе инструмента (это прямая экономия токенов).

Отключение в любой момент: `/laya-all off`.

## Адресное применение и проверка режима

Допускай только on/off, без аргумента on. Неизвестное значение отклоняй до CLI: оно может включить режим. Прочитай status до и после переключения. Проверь фактические risk/done/router/sessionContext и путь конфигурации. Ошибку health отличай от ошибки записи.

| Условие | Действие |
|---|---|
| Инструмент помогает текущей задаче | Применить его с проверкой результата |
| Малый достаточный фрагмент | Читать напрямую |
| Усечение или низкая уверенность | Расширить данные и проверить исходник |
| Противоречие или сбой Laya | Продолжить обычными инструментами |
| Решение о безопасности или завершении | Требовать факты и подходящие проверки, а не confidence |

Не вызывай все инструменты ради чек-листа. Повторяй запрос только при новых данных. Pinned-контекст сохраняй; архив должен допускать восстановление. Ранжирование не отменяет проверку критичного кода. Laya не отменяет штатные разрешения.

Режим записывается в конфигурацию и не отключается сам по окончании задачи. Off задаёт shadow/report/log/sessionContext=off, а не восстанавливает прежние индивидуальные значения. В отчёте — фактический режим, полезные результаты и ограничения; экономия только по измерению.
