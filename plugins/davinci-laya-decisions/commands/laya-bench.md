# Замер производительности Laya

Замерь производительность локальной Laya перед тем, как включать активные режимы гейтов. Выполни в Bash:

```
node "${ZCODE_PLUGIN_ROOT}/scripts/laya-admin.mjs" bench 40
```

Число после команды — количество прогонов. Для этой команды без аргумента используй 40; собственный default CLI — 30.

Покажи пользователю:
1. p50/p95 end-to-end (включая HTTP и сериализацию) и среднее серверное время успешных вызовов (`elapsed_ms`); различие статистик не позволяет точно вычислить расходы адаптера.
2. Вывод `/benchmark` сервера (p50/p95/p99, rps) — это результат серверного сценария с concurrency=1.
3. Вывод о допустимости таймаута гейта: сверь фактический timeoutMs и ошибки; низкий p95 короткого сценария не гарантирует отсутствие таймаутов на реальной нагрузке.

Не сравнивай эти числа с маркетинговыми обещаниями из статей: это замер на этой машине и этой сборке, только он имеет значение.

## Условия и корректная интерпретация

Аргумент — положительное целое число прогонов, без аргумента 40; подставь проверенное число в пример. Перед замером запиши время, адрес, checkpoint и режимы через status. CLI выполняет один прогрев, короткий фиксированный state и последовательные вызовы; /benchmark запускается с concurrency=1.

| Показатель | Ограничение |
|---|---|
| E2E p50/p95/max | При сбоях выборка смешанная; укажи число ошибок |
| elapsed_ms | CLI выдаёт серверное среднее успешных вызовов, не серверные p50/p95 |
| Разница времён | Включает транспорт, очередь, сериализацию и другие расходы; разные статистики напрямую не вычитать |
| /benchmark | Серверный сценарий с указанными входом и concurrency, не универсальная пропускная способность |
| Малое число прогонов | Хвостовые квантили нестабильны |

Сверь фактический timeoutMs хуков и бюджет внешнего запуска. Порог 300/1000 мс сам по себе не доказывает допустимость таймаута. Для приёмки ask/block нужны реальные размеры state, длинные входы, конкуренция и доля превышений таймаута. Стандартный CLI не выдаёт все эти данные: не выдумывай их и обозначь неполную приёмку.

Отчёт: условия, фактические числа, ошибки, ограничения и следующий необходимый замер. Недоступный /benchmark означает отсутствие данных. Режимы автоматически не переключай.
